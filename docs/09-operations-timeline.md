# 09. 迁移流程与失败恢复时间线（脱敏）

> 本文只描述流程和失败类型，不记录任何真实机器、磁盘序列号、文件数量、数据量或日期。  
> 时间线使用相对阶段（T0、T1...），不是性能承诺。

## 1. 背景

- 源盘：单块磁盘上的 LDM 动态盘；
- 卷：NTFS 简单卷，可能由多个 extent 组成；
- 目标：迁移到独立暂存盘，重建为 MBR 基本盘，再回拷；
- 恢复目录与暂存目录可以合并，但必须与 `DATA` 子目录分开。

## 2. 阶段时间线

| 阶段 | 操作 | 结果 |
|---|---|---|
| T0 | 只读预检：磁盘/卷/extent/MBR/启动属性 | 通过 |
| T0+ | 完整镜像/暂存副本准备 | 完成并逐块校验 |
| T1 | 数据复制到暂存盘 | 完成 |
| T1+ | 源 → 暂存全量比较 | 0 mismatch |
| T2 | 第一次重建尝试 | **失败**：DiskPart 未选中磁盘，clean 未执行 |
| T2+ | 只读诊断 | 确认 LDM 分区仍在、卷 offline |
| T2+ | 恢复挂载：`online volume` + `assign letter` | 源卷恢复，数据完整 |
| T3 | 修复 DiskPart 调用为 `/s`，重试 | 通过 |
| T3+ | 源 → 暂存再次全量比较 | 0 mismatch |
| T3+ | 卸载、clean、初始化 MBR、建分区、格式化 | 成功 |
| T4 | 暂存 → 新基本盘回拷 | 完成 |
| T4+ | 新基本盘全量比较 | 0 mismatch |
| T4+ | `chkdsk /scan` | 无问题，0 坏扇区 |
| T5 | 最终验收 | MBR 基本盘、NTFS/Healthy、文件数与暂存一致 |
| T5+ | 删除旧镜像 | 用户确认后执行；仅保留暂存数据副本 |

## 3. 验收结论

```text
源 → 暂存比较   全量逐字节，0 mismatch
暂存 → 新盘比较 全量逐字节，0 mismatch
chkdsk          无问题 / 0 坏扇区
SMART           无新增未校正读取错误
最终磁盘        MBR 基本盘、NTFS/Healthy
```

不记录具体文件数、目录数、字节数或耗时，避免把单台机器的数据带入公共文档。

## 4. 失败与修复

第一次重建失败的原因不是磁盘，而是 DiskPart 交互时序：

- `select disk <N>` 没有生效；
- `clean` 没有执行；
- `SourceDestroyed=true` 被提前写入；
- 源卷只是被 dismount，盘符消失。

修复：

- 改用 `diskpart /s` 命令文件；
- 只在 clean 成功后写状态；
- 失败后先诊断，不格式化；
- 用 `online volume` + `assign letter` 恢复挂载。

详见 `06-diskpart-postmortem.md`。

## 5. 经验

1. **复制快不代表安全**：真正耗时的是全量比较。
2. **失败时先看证据**：盘符消失不等于数据丢失。
3. **状态标志要晚写**：先做，再记录。
4. **日志/杀毒软件会造成 mismatch**：要分类，不要盲目重试。
5. **删除镜像要晚**：至少等重启和关键应用验证之后。
6. **两盘环境**：恢复日志可以和暂存同盘，但 `DATA` 必须独享子目录；恢复镜像仍建议独立盘。
