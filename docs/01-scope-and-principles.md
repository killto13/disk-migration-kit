# 01. 范围与设计原则

## 1. 适用范围

本项目面向以下场景：

- Windows 10/11；
- 一块**非系统、非启动**的物理磁盘；
- 该磁盘当前是 LDM 动态盘；
- 动态卷是同一磁盘上的“简单卷”，可能包含多个 extent；
- 文件系统为 NTFS；
- 用户可以在另一块健康磁盘上准备暂存空间；
- 目标是迁移数据后，把原磁盘重建为 **MBR 基本盘**。

## 2. 不适用范围

以下场景不要直接使用本项目：

- 系统盘、启动盘、页面文件盘、休眠盘、故障转储盘；
- 跨磁盘的动态卷、带区卷、镜像卷、RAID-5；
- Storage Spaces、硬件 RAID、BitLocker 加密卷；
- 已经出现坏道、SMART 失败或频繁掉线的源盘；
- 需要“原地无损转换”的场景；
- 需要保留原 LDM 分区表或原磁盘签名的场景；
- 需要 100% 应用一致性快照的数据库/虚拟机磁盘。

## 3. 为什么需要“迁移后重建”

一个普通 MBR 基本分区只能描述一段连续的物理扇区。动态卷的 extent 可能：

- 逻辑顺序与物理顺序不同；
- 第一个 extent 位于高地址，第二个位于低地址；
- 分区表项 `0x42` 只表示“这是 LDM 容器”，并不描述 NTFS 卷的起始位置。

因此：

```text
MBR 0x42 → 0x07 + 起始 LBA 改成低地址
```

不是“无损转换”，而是让 NTFS 从一个错误的卷首开始读。轻则无法挂载，重则写入错误位置。

可靠路线只有：

1. 把数据完整迁移到独立磁盘；
2. 全量校验；
3. 重建目标盘为基本盘；
4. 回拷；
5. 再次全量校验。

## 4. 设计原则

### 4.1 先验证，后破坏

源盘在暂存副本通过**全量逐字节比较**之前，绝不清空。

### 4.2 身份优先

不以“磁盘 <N>”作为唯一识别条件。至少同时匹配：

- 型号；
- 序列号；
- 固件；
- 容量；
- 启动/系统属性。

序列号是最后一道门禁。

### 4.3 失败关闭

任何不满足的条件都停止，不“跳过继续”：

- 序列号不匹配；
- 源卷不健康；
- 暂存空间不足；
- 比较出现 mismatch；
- 目标盘是启动盘；
- 无法安全卸载源卷；
- DiskPart 输出异常。

### 4.4 证据链

每一步都留下：

- 命令和完整输出；
- 开始/结束时间；
- 目标序列号；
- 文件数/字节数；
- 比较进度 CSV；
- 失败标记和错误原文。

### 4.5 最小写入

- 复制阶段只读源盘；
- 重建阶段只写目标盘的必要元数据/分区/文件系统；
- 回拷阶段只写新基本盘；
- 不在源盘上“修一修试试”。

### 4.6 可恢复

失败时优先恢复挂载，而不是重新格式化：

- 如果只是卷被 dismount：`online volume` + `assign letter`；
- 如果 clean 已执行：从暂存副本或整盘镜像恢复；
- 如果只是比较失败：保留暂存副本，修复差异后重试。

## 5. 关键术语

| 术语 | 含义 |
|---|---|
| LDM | Logical Disk Manager，Windows 动态盘管理 |
| 动态盘 | 使用 LDM 数据库管理卷的磁盘 |
| 基本盘 | 使用传统 MBR/GPT 分区表的磁盘 |
| extent | 动态卷在物理磁盘上的一段连续区域 |
| MBR | Master Boot Record，主引导记录 |
| VBR | Volume Boot Record，卷引导记录（NTFS 引导扇区） |
| 暂存盘 | 存放完整数据副本的独立健康磁盘 |
| 恢复镜像 | 源盘逐字节镜像，用于最坏情况恢复 |

## 6. 决策树

```text
源盘是动态盘？
├─ 否 → 不需要本项目
└─ 是
   ├─ 是系统/启动盘？ → 停止，改用 WinPE/系统迁移方案
   ├─ 有跨盘 extent / RAID / Storage Spaces？ → 停止，需专门方案
   ├─ 有坏道 / SMART 失败？ → 先做只读镜像/专业恢复，不要重建
   └─ 单盘简单卷
      ├─ 有独立健康暂存盘？ → 复制 → 校验 → 重建 → 回拷 → 校验
      └─ 没有 → 先准备磁盘；不要直接清盘
```
