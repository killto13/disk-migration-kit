# 10. FAQ

## Q1. 为什么不能直接 `diskpart convert basic`？

Windows 自带转换要求先删除所有卷。对装有数据的动态盘，这等于清盘。它不是无损转换。

## Q2. 为什么不能把 MBR 的 `0x42` 改成 `0x07`？

`0x42` 只表示“LDM 容器”。动态卷的 extent 可能逻辑顺序反转，卷首不在低地址。把分区类型改成 `0x07` 并指向低地址，会让 NTFS 从错误位置读取 VBR/MFT。

## Q3. 为什么要复制两次、比较两次？

- 第一次比较证明暂存副本完整，才有资格清盘；
- 第二次比较证明回拷后的新盘完整，才能宣称成功。

少任何一次都可能把“复制错误”当成“迁移成功”。

## Q4. 暂存盘需要多大？

至少能容纳源数据量 + 余量。若已有暂存副本，只需补差异 + 安全余量；但首次迁移应按完整数据量准备。

## Q5. 为什么比较会出现日志 mismatch？

日志/缓存/临时文件在复制或比较期间仍在变化。应停止写入服务，或明确排除日志目录并记录差异。不要为了“通过”而忽略用户数据 mismatch。

## Q6. 为什么 `SourceDestroyed=true` 但数据还在？

状态标志可能被提前写入（本次事故就是这样）。以磁盘/分区/卷的实际状态为准，不要只信标志。

## Q7. 盘符消失是不是数据没了？

不一定。常见原因是卷被 dismount/offline。先检查：

```text
list disk
select disk <N>
detail disk
list volume
```

如果 LDM 分区还在，尝试 `online volume` + `assign letter`，不要格式化。

## Q8. 为什么不用 `chkdsk /f`？

`/f` 会修改文件系统。源盘出现问题时，应先做只读镜像/诊断，避免修复动作改变证据或造成二次损坏。

## Q9. 为什么 Robocopy 有时很慢？

可能原因：

- `/IPG` 人为限速；
- 大量小文件；
- 机械盘随机 I/O；
- 杀毒软件扫描；
- 活日志/锁定文件重试；
- 单线程复制。

`/MT` 可以提高多文件吞吐，但它与 `/IPG`、`/EFSRAW` 存在兼容性限制，不能盲目叠加。

## Q10. 可以用于系统盘吗？

不建议。系统盘涉及启动、页面文件、恢复环境、驱动和权限；应在 WinPE/离线环境使用专门系统迁移工具。

## Q11. 可以用于 BitLocker/Storage Spaces/RAID 吗？

本项目未验证。BitLocker 需要先解锁/挂起；Storage Spaces/RAID 的卷映射不同。不要直接套用。

## Q12. 成功后可以立刻删除镜像吗？

不建议。至少等：

1. 全量比较通过；
2. `chkdsk /scan` 无问题；
3. 成功重启一次；
4. 关键应用可用；
5. 用户确认。

删除前确保还有一份独立副本。

## Q13. 为什么脚本要用管理员/SYSTEM？

`diskpart clean`、`Initialize-Disk`、`Format-Volume`、`chkdsk /scan` 等需要提升权限。普通用户会失败或只看到部分磁盘。

## Q14. 为什么不用单个连续 MBR 分区“直接替换”？

因为动态卷的逻辑字节流不是从低地址开始的。单个连续分区只能描述一段连续物理扇区，无法表达“高地址先读、再回卷到低地址”。

## Q15. 这个项目适合谁？

适合：

- 有独立备份/暂存盘的管理员；
- 愿意在 VM/克隆盘上先验证的人；
- 需要理解 LDM/extent/比较/恢复流程的人。

不适合：

- 想要一键无损转换的普通用户；
- 没有备份、没有暂存盘的人；
- 系统盘/RAID/BitLocker 场景。
